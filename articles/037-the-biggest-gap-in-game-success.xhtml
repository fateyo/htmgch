游戏成功中最大的缺口

原文标题：The biggest gap in game success

Demo 策略 课程、书籍与服务

三句话概括

文章认为，独立游戏成功链条中最大的断点，是团队往往需要资金和曝光来做出 Demo，却又必须先有一个能证明市场牵引力的 Demo，才更容易拿到发行、众筹或平台曝光。作者从 2025 年 Staying Inside Conference 的多位嘉宾观点出发，强调 Demo 不只是验证玩法的原型，而应接近最终美术、可玩且能公开展示。文章建议团队以 Demo 优先来组织开发、控制规模，并利用 game jam、政府资助或小额早期投资跨过从想法到 Demo 的资金鸿沟。

浓缩短文

作者在 2025 年 Staying Inside Conference 进行到一半时，发现今年会议中反复出现的主题是：在扩大开发规模之前，Demo 的重要性远超许多团队的预期。Jason Della Rocca 提到，向发行商展示一个已经证明有“牵引力”的 Demo，是获得签约最容易的方式之一。Hooded Horse 签下《9 Kings》就是一个例子，因为这款游戏此前是 Steam Next Fest 中表现最好的 Demo 之一。ICO Partners 的 Thomas Bidaux 也认为，在没有可玩 Demo 之前，不应该贸然启动 Kickstarter。Playstack 的传播总监 Wout van Haldren 在谈《Balatro》营销时也会提到，他们正是通过 LocalThunk 做出的优秀 Demo 发现了这款游戏。作者自己在两小时演讲中也强调，在 Steam 上，基础可见性通常要等到你有 Demo 之后才真正开始。

这里说的 Demo 不是一个用来证明“玩法有趣”的纵切原型，而是应该有接近最终品质的美术、已经打磨好的核心玩法循环，最好还包含第二层循环，并且整体看起来像最终游戏。问题在于，这会造成一个典型的鸡生蛋、蛋生鸡困境。团队需要钱和曝光，所以想找发行商；但没有 Demo，很难拿到发行商；没有钱，又很难做出足够好的 Demo。转向 Kickstarter 也不轻松，因为支持者同样需要一个 Demo 来判断项目是否可靠。

作者并不以工作室负责人或制作人的身份给管理建议，而是从产品和营销角度提出一些“Demo 优先”的粗略思路。团队从最早的原型开始，就应该思考这个原型未来如何变成一个公开可玩的 Demo。开发优先级要围绕可玩性展开，暂缓那些只会在后期出现的功能，先把能公开展示的内容做出来。

团队规模也应该在 Demo 被验证之前保持小。新工作室可以先保持合作关系开放，等 Demo 发布并取得好结果后，再决定是否组成完整合伙结构；这种做法需要咨询律师并准备合同。美术、设计等岗位也可以先采用短期合同，期限覆盖到 Demo 完成并公开。如果表现好，再转为全职团队。所有人的工作都要集中在 Demo 中能被玩家看到的内容上，而不是提前花几周设计最终 Boss。

另一条路径是从 game jam 出发。像《Peglin》和《Dome Keeper》都源于 game jam，并在早期获得了明显关注。两天做出的 game jam 版本通常太粗糙，不能直接作为 Steam Demo，但如果再花几个月抛光、重构原始概念，就有可能达到公开 Demo 的标准。

如果团队所在国家或地区有艺术资助、创业基金等政府项目，也可以把这些钱用来跨过“从想法到 Demo”的阶段。许多这类资金不一定要求已有 Demo，正好可以帮助团队做出 Demo，再去解锁 Kickstarter、发行商或下一轮融资。

作者也把这个问题指向发行商和投资人。行业正在意识到，“想法”和“pitch”并不足以卖出一个项目，但从想法走到 Demo 的基础设施仍然不足。对有资本的人来说，这恰恰是机会：应该有更多小额资金和项目，支持一两个人的团队在几个月内把 Demo 做到可以公开。

最后，文章回到作者长期强调的观点：独立团队不应该把梦想大作当成第一款游戏。更小、更聚焦的游戏可以帮助工作室建立名字和粉丝基础。对于一个从未发售过作品的团队来说，直接投入多年项目非常冒险，因为你还没有证明自己能把游戏做完并发售，发行商和 Kickstarter 支持者自然也更难信任你。
