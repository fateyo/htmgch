游戏开发中消失的中间层

原文标题：The missing middle in game development

打开原文

发售节奏与窗口 品类、标签与市场定位 定价、折扣与收入 Steam 平台与商店机制 失败复盘与避坑

三句话概括

文章提出现代独立游戏开发存在“缺失的中间层”：开发者不是做周末 game jam 小品，就是押上多年做必须赚数十万美元的大项目，中间缺少 1 到 9 个月完成、收入目标 10,000 到 40,000 美元的“中型游戏”。作者借 John Romero 和 id Software 的历史说明，早期开发者通过大量小项目积累技术、市场反馈和工具资产，最终才做出《Wolfenstein 3D》和《DOOM》。文章建议独立团队重新学习小规模商业游戏，把快速发布、复用技术和低风险试错当成职业成长路径。

浓缩短文

作者用 John Romero 和 id Software 的历史提出一个现代独立游戏悖论。1990 年代没有数字发行，开发者需要 Softdisk 这样的公司帮忙出版、制造和邮寄游戏；没有 Unity、GameMaker、Godot 或 Unreal，每个项目都要有人像 John Carmack 那样用 C 或机器码从头写引擎；没有普及的互联网、云端源代码管理和远程协作。可即便条件如此艰苦，id Software 的成员曾经一年做出 13 款游戏。今天工具更好，协作更方便，数字发行几乎没有边际成本，独立开发者理论上应该更敏捷，但很多新团队一上来就做四年项目。作者强调，这不是在说开发者懒，大家都很拼；问题是产业结构和开发者预期把一个重要成长台阶挤没了。

这个被挤掉的台阶就是“中间层”。过去十多年，很多首次创业的独立团队路径类似：三个人做了一个 game jam 游戏，发到 itch.io 后反响不错，于是成立公司、找发行商，准备花三年做第一款商业游戏，目标看似谦虚，只想赚 300,000 美元。作者认为这正是问题所在。现代独立开发常在两个极端之间跳跃：要么做周末完成、免费发布的 jam 小品，要么辞职押注多年、只有赚到数十万美元才算成功的大项目。中间那类比 game jam 更完整、更打磨，但不是 30 小时史诗级“triple-I”独立大作的游戏，反而被忽视了。

作者把这种项目称为“middle game”。它的开发周期应在 1 到 9 个月之间，收入预期是 10,000 到 40,000 美元。这样的收入在今天一些独立开发论坛，尤其是 r/gamedev 的语境里，可能会被视为失败，甚至被嘲笑。但在作者看来，中型游戏曾经是职业建设的常态。它们让开发者练习发布、积累技术、建立作品目录、获得少量收入，并在低风险环境中学习市场。作者认为，现代独立商业模式跳过中型游戏，是 Steam 上 75% 工作室只发布过一款游戏的重要原因之一。

为什么中间层会消失？作者认为，核心原因是产业不再直接为这类游戏付钱。John Romero 在《Doom Guy》中提到，他第一次靠游戏获得报酬，是把 Apple II 游戏《Scout Search》发表在 inCider Magazine，稿酬 100 美元，相当于 2023 年约 300 美元。早期软件杂志甚至会把源代码印在纸上，读者手动输入电脑运行，所以游戏必须足够小，报酬也只是几百美元。后来 Softdisk 会以固定费用买断游戏随月度软件磁盘发行，曾与 John 的 id Software 达成 6 款游戏协议，每款 5,000 美元，相当于 2023 年约 11,000 美元。Flash 游戏时代，Kongregate、Armor Games、Newgrounds 等门户会花约 10,000 到 30,000 美元让开发者把平台 logo 嵌入游戏。那时独立游戏有收入天花板，没人指望一款游戏暴富，于是开发者被激励去做许多小而快、有趣的游戏。赚 15,000 美元不是“失败”，只是行业预期。

后来独立游戏乌托邦改变了心理模型。少数大成功案例让开发者相信，独立游戏也可以像小型 AAA 一样长期开发、一次爆发。与此同时，AAA 体量膨胀，平台、发行商和投资机构也成长起来，行业叙事越来越围绕大项目和高回报展开。例外变成了规则，开发者逐渐忘了小商业游戏是什么样。作者并不是否认《Hollow Knight》《Factorio》这类大体量独立游戏的价值，而是说它们扭曲了新团队对规模的判断。首次项目如果直接瞄准这种量级，往往会在没有市场反馈、没有发布经验、没有现金流的情况下消耗多年。

id Software 的成长路径展示了另一种模式。《Catacomb》是 2D 地牢游戏；《HoverTank 3D》在 1991 年发布，是 id Software 第一个真正的 3D 引擎作品，墙面只是纯色，控制也不够好，但已经有雷达等 FPS 后来常见的界面元素；《Catacomb 3-D》同样在 1991 年发布，基于《HoverTank》引擎加入了纹理墙面、更好的控制、多种武器、钥匙、治疗药水和指南针，但核心设计仍然延续 2D《Catacomb》的地牢探索、Bolt、Nuke、Heal、Key 和分数系统；《Wolfenstein 3D》在 1992 年发布，继续建立在此前 3D 引擎基础上，升级为 VGA 图形，加入隐藏墙、更好的武器和声音触发警卫等机制；到 1993 年《DOOM》发布时，它才真正以新引擎带来革命，包括衰减光照、天空纹理、不同高度地面、非正交墙体和跑动时的头部晃动。

《DOOM》不是凭空出现的天才奇迹，而是多年小项目、市场反馈和持续迭代累积的结果。如果 id Software 采用今天常见的“全押一个三年项目”方式，他们会在没有市场反馈、没有由项目资助的引擎研发、没有 3D 关卡设计练习、没有受众积累的情况下闭门开发，很可能无法做出同样的作品。John Romero 还开发了 Tile Editor，也就是 TED，用于 id Software 多款游戏的关卡制作。这个工具足够灵活，可以服务 2D 平台游戏《Commander Keen》，也能服务《Wolfenstein 3D》这类早期 3D 游戏。Romero 曾表示 TED v5 被用于制作超过 33 款游戏。工具复用本身就是中型游戏路径的价值之一。

作者认为，现代开发者需要重新学习“小而完整的商业游戏”是什么。很多人听到“六个月做一款游戏”会本能反驳不可能，因为 AAA 和顶级独立大作已经改变了大家对游戏规模的感知。但如果只花三个月做一款游戏，哪怕只有 123 条评测，也可能按投入时间计算相当划算。文章举了 Sokpop collective 的例子。Sokpop 基本每月发布一款游戏，背后其实是四名开发者错峰独立制作，每个项目通常约三个月。他们的销售波动很大，因为类型切换很快，也没有总是加倍投入已验证类型。但他们持续发布有趣作品，而且最成功的往往是 Steam 偏好的 craft、build、strategy 相关游戏，如《Pyramida》《Stacklands》《Tuin》《Guardener》《Luckitown》。较弱的则多是平台跳跃、线性叙事和实验性类型。

《Luck be a Landlord》也是中型游戏代表。开发者 Dan DiIorio 表示，这款反资本主义老虎机 roguelike 从概念到在 Steam Game Festival: Autumn Edition 发布首个公开 demo，大约只用了两个月。它最初来自 itch.io 上的 LOWREZJAM 2020，后来才扩展成更大项目。恐怖游戏同样适合这一模式。DMNT Interactive 在 Reddit 上说，《DON’T LOOK AWAY》和《BACKROOMS: APPREHENSION》各用了大约一个半月完成并以抢先体验形式发布，虽然没有赚到数百万美元，但收入足以让他辞职继续做游戏，这正是他的目标。

作者承认，Steam 算法确实不偏爱小型游戏，快速发布许多小作品也不能保证赚大钱。但中型游戏的目的不是立刻成为下一个神作，而是改进技术、练习上线、建立名字、积累后续目录，并在低风险下获得乐趣。如果一个三个月项目失败，损失也只是三个月，可以继续下一个。如果达到 10,000 美元收入目标，就已经是很好的结果。与其花每学期数万美元上游戏设计学校，不如通过发布一批中型游戏来学习，甚至赚到几万美元。id Software 做《HoverTank》和《Catacomb 3-D》时，不会说“我们只赚了 5,000 美元所以失败了”，而是把它看作通往《Wolfenstein 3D》的带薪研发。后者一年后为 id Software 带来每月 50,000 美元收入。

文章最后引用 John Romero 在《Doom Guy》中的建议：从小处开始，练习，先尝试复刻经典街机游戏，再去挑战大型 RPG。Carmack、Tom 和 Romero 在合作前各自已经做了十年游戏，又过了几年才做出《DOOM》，而《DOOM》是 Romero 的第 90 款游戏。作者希望现代独立开发者允许自己经历“中间阶段”，允许作品不完美，允许快速试错。宏大的代表作可以以后再做，但前提是先通过一批小而完整的游戏，把技术、审美、商业判断和发布能力练出来。
